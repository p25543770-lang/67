# Depth Studio

Depth Studio — приложение для просмотра потока глубины и экспериментального накопления облака точек помещения. Есть автономный деморежим и модульная архитектура источников данных.

> **Честный статус датчиков.** В текущей версии реализован только экспериментальный путь чтения Kinect 360 / Kinect v1 через libfreenect. Проверки этого адаптера на физическом устройстве и Windows в репозитории нет, поэтому он **не обозначен как проверенная поддержка**. Kinect One (v2), Azure Kinect и Intel RealSense перечислены в интерфейсе и документации, но их интеграционные модули пока не реализованы и источники отключены. Обычная RGB-камера не считается датчиком глубины.

## Что умеет приложение

- Работать в деморежиме без датчика, Python, драйверов и локального моста.
- Показать цветной кадр и карту глубины (для Kinect v1 при наличии работающих RGB- и depth-потоков; в демо используются синтетические изображения).
- Собирать облако точек и совмещать кадры экспериментальным ICP через Open3D.
- Показывать скорость перемещения и предупреждать о слишком быстром движении или потере трекинга.
- Остановить сканирование, очистить накопленное облако и экспортировать точки в ASCII PLY или vertex-only OBJ.
- Показать статус модуля, требования к драйверу и понятные ошибки.

Экспорт PLY/OBJ содержит **вершины облака точек, не полигональную сетку**. В OBJ намеренно нет граней. ICP может дрейфовать, особенно на однотонных стенах, при резком движении, недостаточном перекрытии кадров или движущихся объектах. Цвет и глубина Kinect v1 не совмещаются в общей системе координат. Это исследовательский прототип, а не измерительный инструмент.

### Архитектура датчиков

Каждый источник находится в своём модуле каталога `sensor_drivers/` и следует контракту `SensorAdapter` из `sensor_drivers/base.py`. Каталог сообщает отдельно о наличии реализации, зависимостей и аппаратной проверки. Будущие адаптеры нельзя отмечать как поддержку только по факту установленного SDK; перед включением источника нужны функциональные тесты с реальным датчиком.

## Демо и запуск интерфейса

Для разработки интерфейса нужен Node.js 20+:

```bash
npm ci
npm run dev
```

Откройте адрес Vite, обычно `http://localhost:5173`. Демо запускается автоматически. Нажмите «Начать сканирование», чтобы увидеть синтетическое накопление данных; выберите PLY или OBJ для тестового экспорта. Демо-данные не являются измерениями помещения. Удалённый предпросмотр в браузере не имеет доступа к датчику, подключённому к компьютеру пользователя: для реального сканирования приложение и мост нужно запускать локально на Windows-машине с устройством.

На Windows можно запустить `start-windows.bat`; он установит npm-пакеты при необходимости, запустит Vite и откроет браузер. Сам по себе этот режим не подключает датчик — для аппаратного моста отдельно запустите Python-сервер.

## Экспериментальный Kinect v1

Сначала подключите Kinect 360 к питанию и USB. Подготовьте совместимую с вашим Windows версию [libfreenect](https://github.com/OpenKinect/libfreenect) и её Python-привязки `freenect`. Инструкция по установке libfreenect и выбору USB-драйвера зависит от сборки и Windows; этот проект не поставляет и не устанавливает драйвер. Не переключайте USB-драйвер наугад: это может нарушить работу других Kinect-приложений.

Рекомендуется Python 3.11 x64 (для него доступны совместимые сборки NumPy/Open3D). Установите дополнительные зависимости в **тот же интерпретатор**, которым будете запускать сервер:

```powershell
py -3.11 -m pip install -r requirements-scan.txt
py -3.11 -c "import freenect, numpy, open3d; print('Python-зависимости найдены')"
```

`freenect` — native-привязка libfreenect, она не устанавливается надёжно обычной командой `pip install freenect`; подготовьте её по инструкции выбранной сборки libfreenect. Если импорт `freenect` не проходит, меню Kinect покажет диагностическую ошибку. Наличие Microsoft Kinect SDK не заменяет эту привязку.

Запустите в одном терминале локальный мост:

```powershell
py -3.11 server.py
```

В другом терминале запустите интерфейс:

```powershell
npm run dev
```

Затем в приложении выберите **Kinect 360 (v1)**, нажмите «Обнаружить датчики», после успешного обнаружения — «Подключить выбранный источник». Кнопка запуска сканирования начнёт накопление. Перемещайте сенсор плавно, ориентировочно не быстрее 0,45 м/с, держите часть неподвижных поверхностей в соседних кадрах. Включите паузу или остановите сканирование, затем экспортируйте облако.

Мост слушает только `127.0.0.1:8765`. Vite и Electron проксируют `/api` на локальный мост. Если порт занят, задайте одинаковое значение `DEPTH_STUDIO_PORT` перед запуском сервера и приложения (в PowerShell: `$env:DEPTH_STUDIO_PORT=8766`).

## Установщик Windows `.exe`

Конфигурация настроена на NSIS-установщик с выбором папки установки, ярлыками «Пуск» и рабочего стола. На Windows x64 с Node.js 20+ выполните:

```powershell
npm ci
npm run build:win
```

Готовый файл будет в `release/Depth-Studio-Setup-1.1.0-x64.exe` (имя зависит от версии). Workflow **Build Windows installer** также собирает `.exe` на Windows runner; откройте успешный запуск GitHub Actions и скачайте артефакт **Depth-Studio-Windows-Installer**.

Установщик не подписан сертификатом, поэтому Windows SmartScreen может показать предупреждение. В него включены интерфейс и Python-мост, но **не** включены Python, NumPy/Open3D, libfreenect и USB-драйверы. Поэтому установленное приложение работает в демо-режиме без дополнительного ПО; реальный Kinect требует ручной подготовки перечисленных зависимостей. Сборка установщика не означает аппаратную проверку датчика.

## Диагностика

- **«Локальный мост не запущен»** — демо продолжает работать. Для устройства запустите `py -3.11 server.py` и убедитесь, что порт 8765 свободен.
- **Не найден `freenect` или NumPy** — установите libfreenect с Python-привязками и NumPy в интерпретатор запуска `server.py`.
- **Нет Open3D** — выполните `py -3.11 -m pip install -r requirements-scan.txt`.
- **Датчик не обнаружен** — проверьте блок питания, USB-подключение, драйвер libfreenect и не занято ли устройство другим приложением.
- **RGB-поток отсутствует** — адаптер может продолжить работу только с глубиной; отдельная калибровка и регистрация цвета пока не реализованы.
- **Потеря трекинга / быстрое движение** — замедлите сенсор, верните в кадр уже просмотренную статичную поверхность и избегайте пустых однотонных стен.

## Разработка и проверки

```bash
npm run build
npm run test:python
```

Для разработки API-сервера достаточно стандартной библиотеки Python. Реальный поток требует сторонних привязок и физического Kinect v1; без них тестируйте деморежим. Модульные проверки не заменяют аппаратные испытания.
